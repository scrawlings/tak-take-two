# 02 — Keyboard shortcuts on the game screen

**What to build:** A focus-guarded shortcuts layer for the game screen: `Enter` plays the move, `[` `]` step the history scrubber, `u` requests a take-back, `Esc` cancels an in-progress board move or snaps back to live, `?` toggles a one-line help panel. Shortcuts are inert while focus is in an input/textarea/select (typing PTN never triggers them) and activate existing affordances — no new server routes. Spec: `.scratch/ui-usability/spec.md`.

**Blocked by:** 01 — History scrubber (the `[` `]` bindings and `Esc`-to-live drive its state); agree the scrubber's module interface with 01.

**Status:** done

- [x] A tested shortcuts module in the client bundle (ADR-0006): key → action mapping, focus guard (active only when `document.activeElement` is not an input/textarea/select/contenteditable), no-ops where an action is unavailable (take-back when none may be offered; `[` at the start; `]` at live).
- [x] `Enter` plays the move — the same submit the form button performs, so a composed or typed move in the field is played.
- [x] `u` triggers the existing take-back POST via the affordance that is already rendered (only when `canOfferTakeBack`); `Esc` cancels a builder in progress or snaps to live; `[` `]` step the scrubber.
- [x] `?` toggles a small, dismissible help panel listing the bindings (server-rendered, Alpine-shown like other islands — no new client-only text).
- [x] Tests: module driven as plain data (mapping, guard, no-ops); HTTP seam asserts the help panel exists and the shortcuts script ships on the game page only.

## Comments

**2026-08-19 — Specified in grilling.** Bindings confirmed as proposed: Enter, `[` `]`, `u`, Esc, `?`, all inert while typing. `Ctrl+Z` was explicitly rejected for take-back (browser undo collision). "Activate the same affordances a click would" was the stated principle.

**2026-08-19 — Implemented.** `web/src/client/shortcuts.ts` is a new pure module (ADR-0006 precedent, same shape as `move-builder.ts`/`review.ts`): `resolveShortcut(event, target)` maps a keystroke to one of `'play' | 'back' | 'forward' | 'takeback' | 'cancel' | 'help'`, returning `null` for an unbound key, a modified chord (`ctrlKey`/`metaKey`/`altKey`, so OS/browser shortcuts are left alone), or focus on an input/textarea/select/contenteditable — tested as plain data in `web/test/shortcuts.test.ts`, no DOM.

The Alpine adapter absorbed the wiring into `takBoard` rather than a second component, for the same scope-boundary reason ticket 01 gave: `[`/`]`/`Esc` all read or drive `reviewAt`/`reviewTotal`/`cancel`/`snapToEnd`, which already live there. A window-level listener (`x-on:keydown.window="handleKey($event)"`) sits on the same wrapper div that survives SSE swaps, so the binding is never lost to a stream frame. `handleKey` resolves the action and dispatches: `help` toggles a new `helpVisible` flag; `cancel` prefers `snapToEnd()` over `cancel()` when reviewing (leaving review takes priority over dropping a composition, since the two can't be true at once — reviewing already drops any in-progress composition); `back`/`forward` call a new `step(delta)` that walks the history's `.move-link` elements (found via Alpine's injected `$root`, the same pattern `stream.ts`'s `findRegions` established) and reuses `scrubTo` on the one it lands on; `play`/`takeback` call `submitForm(suffix)`, which finds the form whose `action` ends with the suffix and calls `.requestSubmit()` — the same submit the button already performs, so no new route is opened. An absent or hidden form (no take-back offered, or the move form hidden by review) means nothing matches, which is the no-op for free rather than a special case.

`step`'s boundary rule, settled here since the spec's prose ("no-op when not scrubbed") and the ticket's own checklist ("`[` at the start; `]` at live") read slightly differently: `[` from live enters review at the *last* move — exactly what clicking it would do — so every further `[` is a genuine step backward, and running past move 1 ("the start") is the no-op. `]` from the last reviewed move snaps to live (that position and live are the same one); `]` while already live, with nothing beyond it, is the no-op the checklist names. This keeps `[`/`]` usable to start reviewing from the keyboard alone (user story 6), rather than requiring a prior click.

The help panel (`renderShortcutsHelp` in `views.ts`) is a one-line, server-rendered `<p class="shortcuts-help panel">` toggled by `x-show="helpVisible"`, sitting inside the `takBoard` wrapper so it can read that flag; `renderLegend` gained "Press `?` for keyboard shortcuts." so the binding is discoverable without already knowing it. Ships on the game page only because it is `renderGamePage`'s own markup, not bundle code — verified in `games-http.test.ts` by asserting its absence on `/games` and `/games/find`, which load the same client bundle but never render it.

Tests: `shortcuts.test.ts` (mapping, guard, modifier chords), `board-adapter.test.ts`'s new `describe('keyboard shortcuts', ...)` (each action, the two no-op boundaries, `Escape`'s review-over-cancel priority), `games-http.test.ts`'s new `describe('keyboard shortcuts on the game screen (ticket 02)', ...)` (panel and listener present on the game page, absent from both lists). Full suite green (625 tests), typecheck and lint clean, client bundle rebuilt.

**2026-08-19 — Code review.** Standards and Spec sub-agents found no hard violations and no missing/wrong requirements. Standards flagged the `[`/`]` boundary math (index arithmetic, "stop at start," "snap to live") as living in the adapter rather than the pure module, against ADR-0006's pattern — fixed by extracting `stepReview(reviewAt, total, delta)` into `shortcuts.ts` as pure arithmetic (`{ kind: 'goto', move } | { kind: 'live' } | { kind: 'noop' }`), tested directly on numbers in `shortcuts.test.ts` rather than through mocked DOM; `board-adapter.ts`'s `step` now only turns that answer into a DOM lookup. The other two Standards notes (`takBoard` accreting responsibilities across tickets 01/02; the "scrub" terminology CONTEXT.md marks avoid) were left as-is: both predate this ticket (ticket 01's doing) and the review itself judged them consistent-with-precedent rather than fresh regressions. Spec confirmed the `[`/`]` design, the focus guard, the take-back gating, and the no-new-routes requirement are all correct; its one note (the HTTP test proves the *markup* is page-specific, not that the JS module is unbundled elsewhere) reflects ADR-0007's single-bundle architecture, not a defect. Full suite green (632 tests after the fix), typecheck and lint clean, client bundle rebuilt.
