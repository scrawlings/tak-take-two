# The site's build artifacts are committed files, not inlined strings

The client bundle and the stylesheet were TS strings: `siteCss()` lived inside `web/src/html.ts`, and the vite-built bundle was exported as a committed TS module (`client-script.generated.ts`) that the shell inlined between `<script>` tags. That was ADR-0006's "inline, not a served file" seam, justified by ADR-0002's single-process deployment serving no static files. Both artifacts are now committed files in `web/static/`, served by the app's own routes and referenced by URL — the shell links `/site.css` and loads `/client.js` — while the no-build-step property ADR-0006 bought with the string form survives unchanged.

Status: accepted

## The decision

- **The stylesheet is a committed file, not a string.** `siteCss()` (a 624-line template literal in `html.ts`) moves verbatim to `web/static/site.css`, served by the existing `/site.css` route. `html.ts`'s `renderShell` keeps `<link rel="stylesheet" href="/site.css">` — the page's bytes don't change, only where the CSS lives. This is candidate 6: the shell module no longer owns the design system, and the CSS is editable, lintable, and diffable as CSS.
- **The client bundle is a committed file, not an inlined string.** `build-client.ts` now writes the vite IIFE to `web/static/client.js` plus a fingerprint sidecar (`client.fingerprint.json`), and the shell emits `<script defer src="/client.js">` for pages that ask for the client. The old `client-script.generated.ts` is deleted. The fingerprint test that guarded the string form now reads the committed file and sidecar — same drift guard, same no-build-step property (`npm run dev` and the tests never need the build to have run), because the artifacts are committed.
- **`web/src/static-urls.ts` is the one place that names the asset URLs.** The shell references `SITE_CSS_URL`/`CLIENT_SCRIPT_URL` and the routes serve them, so renaming an asset is one change — the same single-statement pattern ADR-0012's contract module established for attribute names.
- **The glyph table is single-sourced.** The board glyphs (`●○▲△■□`) were declared twice — `views.ts`'s `stoneGlyph` and `review.ts`'s `GLYPH` table, the latter commented "matches `views.ts` exactly." They now live once in `web/src/contract.ts` (ADR-0012's module), and both the server's live board and the bundle's review renderer import the same function. This is the web-side half of candidate 5; it needed no core involvement because the glyphs were already a web-side duplication.
- **The core-side rules facts stay core-guarded.** Candidate 5 also named the carry limit, the reserve counts and the TPS grammar — all mirroring `core/src` in the bundle. Those stay as they are: the bundle still deliberately does not import `@tak/core` (ADR-0006's standalone-module choice; the round-trip tests remain the no-drift guarantee). Single-sourcing them would require either a shared module core also imports (an ADR-0001 core/web-split question) or a generated module — both heavier than the facts today, exactly as the architecture review's candidate-5 discussion concluded. The served-file change removes the *machinery* blocker (a generated rules module would be a normal artifact, not another inlined string) without forcing the decision.

## Considered options

- **Keep the strings; serve them via routes.** Rejected: that is the status quo. `siteCss()` in `html.ts` is candidate 6's named problem, and the inlined bundle's `</script>`-safety check and string-escape tax vanish once the artifact is a file.
- **Serve static files from disk with a static middleware.** Deferred: the app already serves the two assets via its own routes with explicit cache headers; a static middleware buys path-based serving this deployment does not need (ADR-0002's one-process shape is unchanged). If a third asset appears, `static-urls.ts` plus one route is still the pattern.
- **Import `@tak/core` into the bundle to kill the rules duplication.** Rejected (unchanged from ADR-0006): the bundle stays standalone; round-trip tests stay the guard. The served-file change does not alter that reasoning — bundle size stops being per-page-load, but "carry cheaply" was never the only reason.
- **Commit the built files but keep inlining them.** Rejected: inlining a file is the string form wearing a file's clothes; the point is the shell references URLs and the browser caches the assets.
